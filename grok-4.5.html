The short version

What Grok 4.5 actually is

Grok 4.5 is xAI's flagship large language model, released on 8 July 2026. It reads text and images, writes text, and — unlike a plain chatbot — it is designed to think before it answers and to use tools in a loop until a task is genuinely finished.

Three things separate it from the generation before it. It sits on a much larger foundation model (a reported ~1.5-trillion-parameter base, roughly triple its predecessor's). It was tuned specifically on real software-engineering work rather than general chat. And it is unusually frugal: it reaches comparable answers using a fraction of the "thinking" tokens rivals spend, which is what makes long autonomous agent runs affordable.

The tradeoff is equally concrete: the context window was halved from its predecessor's 1M tokens, native video input was dropped, and the price per token went up.

Mixture of experts

1.5 trillion parameters, but not all at once

Grok 4.5 is described as a mixture-of-experts model. The network is split into many specialist sub-networks; a small router reads each token and wakes only a couple of them. That's how a model this large can answer this fast — you pay compute for the experts you actually use, not for the whole brain.

Reasoning effort

A dial between "fast" and "careful"

Before answering, Grok 4.5 writes a private chain of thought. You can set how much of it to write — low, medium, or high. More thinking buys accuracy on hard problems and wastes money on easy ones. Reports at launch say the model runs at high effort by default, which is great for a refactor and overkill for "rename this variable."

Context window

The one number that went backwards

Context is the model's working memory: everything it can see at once — your files, the conversation, tool output. Grok 4.5 holds 500,000 tokens. That is enormous in absolute terms and a 50% cut from Grok 4.3's million.

Working memory, compared

tokens held in one request

1 token ≈ ¾ of an English word. Grok 4.5 adds context compaction — it summarises older turns on the fly — which softens the cut for long agent sessions but does not undo it.

Benchmarks

Fast, cheap, and not always first

Grok 4.5 is a genuine frontier model, but it does not sweep the board. It leads on terminal-style agent work and trails on the hardest patch-writing suites. The honest summary: results depend heavily on which test you pick.

Token economics

The real headline: it thinks less

Benchmarks measure whether a model can solve a task. This measures what the attempt costs. Solving the same average SWE-Bench Pro task, Grok 4.5 emits about 15,954 output tokens; Opus 4.8 at maximum effort emits about 67,020. Same destination, a quarter of the talking.

Pricing

What it costs you

$2.00 per million input tokens, $6.00 per million output. Cache hits drop input to $0.30. Drag the sliders for your own workload — the comparison is against Grok 4.3, which is cheaper per token but markedly less capable.

The fine print

What it gives up

Every model release is a set of trades. These are Grok 4.5's, stated plainly.

Memory

Half the context

500K tokens, down from Grok 4.3's 1M. Compaction helps; it isn't the same thing as having the window.

Modality

Video input dropped

Text and images in, text out. The native video understanding the previous generation shipped with is gone, and it cannot generate images.

Price

Costlier per token

$2/$6 against $1.25/$2.50, and the 20% batch discount went away. Token frugality has to earn that back — on agent work it usually does.

Reliability

More confident, still wrong

A 54% hallucination rate alongside 52% accuracy. Verify anything factual; the fluency is not evidence.

Latency

Slow first token

High-effort reasoning by default means ~12 seconds before the first token appears. Poor fit for interactive autocomplete.

Openness

Closed and unverified

Proprietary, no local deployment, undisclosed parameter count, and launch benchmarks published by the vendor.

Pick it when the job is repository-scale code, a long tool-using agent run, or high-volume knowledge work where per-task cost matters. Look elsewhere when you need million-token prompts, video, image generation, sub-second responses, or on-premise weights.
